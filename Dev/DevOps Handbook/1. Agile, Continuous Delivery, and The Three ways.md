## Value Stream
The process required to convert a business hypothesis into a technology-enabled service or feature that delivers value to the customer.
Value is created only when our services are running in production without chaos and disruption.
## Focus on deployment lead time
Instead of large batches of work being processed **sequentially**, goal is to have testing, deployment, and operation happening **simultaneously** with design/development.
### Lead Time vs Processing Time
![[PXL_20260710_000210464.jpg]]
Lead time is one of two measures used to measure performance in value streams, with the other being processing time.
- **Lead time** starts when the request is made (ticket created) and ends when it is fulfilled.
- **Processing time** omits the time that the work is in queue, waiting to be processed.
### The DevOps ideal
Developers receive fast, constant feedback, enabling them to quickly and **independently**:
1. Implement
2. Integrate 
3. Validate 
4. Deployed
the code in production by: **Checking small code changes**.

Architecture that is modular, well encapsulated, and loosely coupled brings you **autonomy**, with failures being small and contained.
### Flow Metrics to Measure Delivery of Business Value
- Flow velocity: number of flow items that are completed in a set time period. Helps to answer whether value delivery is accelerating.
- Flow efficiency: the proportion of flow items actively worked on to the total time that has elapsed. Identifies inefficiencies like long wait times.
- Flow load: number of active or waiting flow items in a value stream. Helps teams see if demand is outweighing capacity.
- Flow distribution: the proportion of each flow item type in a value stream. Each value stream can track and adjust these depending on their needs in order to maximize the business value being delivered.                                                                                                
## The three ways
![[PXL_20260710_000341458.jpg]]
1. Enable fast left-to-right flow of work by reducing batch sizes. Build in quality by preventing defects and constantly optimize for global goals.
2. Enable the fast and constant flow of feedback. Prevent problems from happening again. Enable faster detection and recovery.
3. Enables the creation of a generative, high-trust culture. It supports a dynamic, disciplined, and scientific approach to experimentation. Also, it can multiply the effects of new knowledge, transforming local discoveries into global improvements.

## Example. DevOps Journey.
### Inputs. What is DevOps?
1. Setting concrete goals
2. Formalizing their toolchain
3. Bringing mentors from outside
4. Experimenting and automating
5. Learn while they were doing (practical training).
### Outputs
Measure:
- Deployment frequency
- Deployment cycle time
- Change failure rate
- Development cycle time
- Number of incidents
- Mean time to recover (MTTR)
### Outcomes. Finance, friend of foe?
The current finance approval process was cumbersome and lengthy.
See where money was actually being invested and question whether that was the best use of it. And Finance was able to gain the visibility they needed to trust there weren't large amounts of waste.
Focus on outcomes:
- Make money
- Improve OPs
